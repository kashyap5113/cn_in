    Understanding the Protocols

    What is Sliding Window Protocol?

    The Sliding Window Protocol is a flow control and reliable data transfer mechanism. The sender maintains a "window" of sequence numbers it is allowed to send without waiting for acknowledgement. As ACKs arrive, the window slides forward, allowing new packets to be transmitted.

    • Multiple packets can be in transit simultaneously
    • Sequence numbers identify each packet
    • ACKs confirm successful delivery
    • Lost packets are detected via timeouts and retransmitted
    • Window size controls flow and congestion

    Go-Back-N (GBN)

    The sender transmits up to W packets. The receiver only accepts the next expected packet — anything out of order is discarded.

    • Receiver window = 1 (no buffering)
    • ACKs are cumulative: ACK n means all packets 0…n received
    • Sender keeps one timer for the oldest unACKed packet
    • On timeout, sender retransmits from base (the entire window)
    • Simpler implementation, wastes bandwidth on loss

    Selective Repeat (SR)

    Both sender and receiver maintain windows of size W. The receiver buffers out-of-order packets and acknowledges each individually.

    • Receiver window = W (buffering enabled)
    • ACKs are individual per packet
    • Sender keeps one timer per packet
    • On timeout, only the missing packet is retransmitted
    • More efficient under loss, but more complex
